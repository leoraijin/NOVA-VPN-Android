Идентификатор: `com.nova.vpn.android.usbtest.completionpreview`.
Название: **NOVA VPN · USB TECNO**. База приложения: 0.2.52.
Она устанавливается рядом с ранее установленной NOVA; настройки, профили и ключи Android Keystore принадлежат отдельному пакету. С разрешения пользователя выполнен временный импорт реальной подписки: 19 узлов без ошибок. Первый узел проверен через оба ядра на двух HTTPS-адресах. После проверки исходное тестовое хранилище восстановлено, временная ссылка удалена.

## Собрать APK без запуска тестов

Из корня Android-репозитория, с закреплённым toolchain:

```powershell
.\Run-Checks.ps1 -Tasks ':app:assembleRealitypreview' `
  -RealitySmoke -UsbTest -UsbTestSlot completionpreview `
  -RealityAbi arm64-v8a -ToolchainRoot '<папка toolchain>' `
  -XhttpPreviewAar '<путь к libbox-arm64-arm-amd64-386.aar>'
```

Здесь Run-Checks запускает только явно переданную Gradle-задачу сборки. Unit/instrumentation задачи не вызываются. Без явного `-Tasks` скрипт запускает unit-тесты. Для локальной диагностики используются только явно выбранные задачи.

Для preview .3 требуется точный SHA-256 AAR:
`598e070a4da697edeac316ca3739f32b9554dcf17ad475346394d5971bae7f92`.

Результат: `app/build/outputs/apk/realitypreview/app-arm64-v8a-realitypreview.apk`.
В этой конфигурации versionName: `0.2.52-reality-preview.3`.

## Текущее состояние

- На TECNO установлена отдельная preview .3, с ядром `1.14.3-lx.23-nova-downlink.3`. Старая NOVA сохранена. Для контролируемого сравнения использовалась и .2; затем .3 возвращена на телефон.
- .3 меняет XHTTP: при отмене upload POST из-за ошибки download сохраняет исходную причину ошибки. Это не исправление DNS/TLS отказа экспериментального Rust Reality Core.
- После разрешения пользователя диагностика возобновлена. Polling-контроль воспроизвёл TCP connect timeout после пересоздания VPN. Исправленный тест ждёт NetworkCapabilities и LinkProperties; 20/20 циклов прошли в том же APK. Полный локальный сценарий обоих ядер на .2 и ещё 20/20 Rust bootstrap/TUN циклов на установленной .3 прошли. Runtime Rust и проверка TLS не ослаблялись.
- Текущие подробные результаты и незавершённые пункты — в COMPLETION-STATUS.md.
- Production AAR, стабильный номер приложения и основная ветка не заменены. Для обновления установленной стабильной версии с сохранением данных по-прежнему нужен её исходный ключ подписи.
- Функции идентификации ограничены хранением и переносом; настоящие HWID/дополнительные заголовки провайдерам не отправлялись.

## Исходники ядра .3

Архив `NOVA-XHTTP-source-1.14.3-lx.23-nova-downlink.3-candidate9.zip` содержит закреплённые исходники, патч, зависимости, лицензии, Go SDK source и сборочные сценарии. Он не содержит пользовательских подписок и ключей подписи.
Независимое восстановление candidate9 и сборка всех четырёх ABI завершены: весь AAR побайтно совпал с каноническим .3. Использованы закреплённые готовые библиотеки Cronet; независимая C++-сборка Cronet и полная XHTTP-матрица на Android остаются отдельными незавершёнными проверками. Локальный Rust bootstrap/TUN на отдельном APK .3 проверен описанным выше объёмом. Выравнивание ELF не доказывает работу на Android с 16 КБ страницами.

## Проверки 26 октября после предоставления реальной подписки

- Реальная подписка: 19 VLESS/TCP/Reality профилей, 0 предупреждений, зашифрованное сохранение/чтение. Первый узел прошёл Cloudflare HTTPS и Google HTTPS на sing-box .3 и Reality Core. Прямой контроль — без VPN, контроль отдельного тестового UID — через VPN. Остальные 18 узлов не объявляются проверенными подключением.
- Все 6 фаз WorkManager на TECNO прошли, включая устаревшие снимки, исчерпание повторов и восстановление после остановки процесса.
- Перенос/восстановление: 8 точек гибели процесса, 5 ошибок и экран повреждённого журнала прошли.
- Оба ядра: применение/откат маршрутов, вытеснение устаревших команд, IPv4/IPv6 и исключённые приложения прошли на искусственных локальных соединениях.
- XHTTP .3: packet-up, stream-up, auto с отдельным download pool прошли через настоящий Android TUN и локальный официальный Xray. Это не вся матрица TLS/Reality/H3.
- В низких окнах исправлены перекрытие содержимого iOS-панелью и чрезмерно большой заголовок One UI. Повторные проверки iOS, One UI и Windows 11 в обеих темах прошли, включая видимость названия над навигацией в альбомном режиме. Material ранее прошёл обе темы без последующих изменений его кода; результаты — native/diagnostic-evidence/tecno-ui-2026-10-26.json.
- Подпись стабильного обновления отложена по просьбе пользователя; работаем с отдельным пакетом. Проверки 30 физических смен сети, длительного сна/батареи и среды с 16 КБ страницами не объявляются завершёнными.
- В отчётах и исходниках нет ссылки реальной подписки и её ключей. Ноутбук использует прежний VPN.

После исправлений итоговый APK повторно прошёл реальную подписку на обоих ядрах. Дополнительно каждое ядро прошло две физические потери/возврата Wi-Fi с сохранением TUN и проверкой IPv4/IPv6; ручное отключение не отменялось возвращением сети. Это не полный длительный прогон.
