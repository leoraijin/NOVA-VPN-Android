# Reality Core — экспериментальное второе ядро Android

Цель: добавить ERGFT/vpn-core, не заменяя основной sing-box и не меняя сохранённые профили.
Это не заявление о готовности к стабильному выпуску. Проверки и ограничения ниже обязательны.

## Границы интеграции

- Основной движок — sing-box. Отсутствующее или неизвестное значение настройки выбирает sing-box.
- Выбор находится в настройках всех четырёх оформлений; изменение запрещено при подключении/работе VPN.
- Один Android VpnService и одно работающее ядро. Автоматического скрытого переключения движка нет.
- Профили и подписки остаются в существующем зашифрованном хранилище; адаптация только в памяти.
- Перед установкой TUN выполняются адаптация и нативная проверка конфигурации.
- Для Reality Core изменение сервера/правил во время подключения отклоняется с предупреждением:
  сначала нужно отключиться. Это исключает окно прямого трафика между остановкой и заменой TUN.
- Android владеет адресами, маршрутами, списками приложений и разрешением VPN. Переданный FD
  принадлежит нативному ядру, включая путь неудачного запуска.
- Сокеты ядра защищаются через VpnService.protect и привязываются к физической сети.
- Проверка HTTPS используется прежняя, через защищённый локальный SOCKS-вход. Одно тихое уведомление.
- Нативные ошибки классифицируются в ограниченный диагностический журнал, без исходного текста,
  адресов, ключей, подписок и UUID. Готовность TUN не выдаётся за подтверждение трафика.
- Периодический локальный опрос терминальных ошибок не выполняет сетевые проверки/пинги.

## Совместимость и ограничения первого эксперимента

- Поддерживаемые прокси-выходы: VLESS и Trojan, только параметры, принимаемые закреплённым ядром.
- VMess, Shadowsocks, Hysteria2, TUIC, произвольные группы и неизвестные параметры не преобразуются
  «приблизительно»: предлагается основной sing-box.
- Правила приложений отдельно поддерживаются через Android Builder. Правила сайтов отдельно —
  через ядро. Их совместное использование пока отклоняется: Android фильтрует приложения раньше
  правил сайтов, тогда как в NOVA на sing-box сайты могут переопределить правило приложения.
- Сложные полные JSON, произвольные TUN-подсети, маршруты и системный DNS не принимаются
  без точной поддержки. Проверка TLS никогда не отключается для обхода несовместимости.
- Для управляемых правил сайтов добавляется отдельный fake-IP DNS-план: приложение получает
  виртуальный IP, а ядро восстанавливает домен до маршрутизации. Исходные DNS-правила сохраняются
  для реального разрешения на direct/proxy пути. Произвольные DNS-планы и конфликтующие fake-IP
  настройки отклоняются. Уже закешированные реальные IP и собственный DoH приложения остаются
  ограничением определения имени; для полного контроля таких приложений используйте sing-box.
- Для сгенерированных настроек NOVA bootstrap DNS использует защищённый direct UDP, а удалённый
  DoH сохраняет имя проверки сертификата. Подмена SNI на IP не допускается.
- Переход между сетями, сон, долгие сессии и устройства с ограниченными ресурсами требуют
  реальных испытаний. Нельзя заявлять выигрыш в скорости/памяти/батарее без измерений.

## Воспроизводимость

Источник: https://github.com/ERGFT/vpn-core

Закреплённый commit: `51a811f1eb3dc3f158b6f7d1a38e3da1d3cf62bc`.

JNI: `native/reality-jni.c`. Дополнения к upstream — отдельные проверяемые patches в `native/`.
Linux-сборка: Rust >= 1.89, cargo-ndk 3.5.4, Android NDK 27.2.12479018, API 24.
Команда: `bash native/build-reality.sh` (все три ABI) либо с одним ABI как аргументом.
GitHub Actions собирает ARM64, ARMv7 и x86_64 отдельно; библиотеки не подтягиваются при работе VPN.
16 KiB page alignment задаётся и Rust, и JNI-линкеру; фактическое ELF-выравнивание проверяется перед выпуском.

## План приёмки

1. Unit-тесты: сохранение движка, прежний default, генерация конфигурации, отказ на несовместимости,
   маршрутизация, DNS, отсутствие секретов в сообщениях; все существующие тесты NOVA.
2. Нативная сборка всех ABI и тесты FFI. Проверка символов, зависимостей ELF, выравнивания.
3. Android smoke: загрузка JNI, проверка конфигурации до TUN, ошибка/закрытие FD, повторные
   запуски/остановки, отсутствие устаревших callbacks и зависших потоков.
4. Реальное устройство: VLESS TLS/REALITY/Vision, Trojan, TCP/WS/gRPC; рабочий и ошибочный профиль.
5. DNS/IPv6: имена серверов, bootstrap, AAAA, сайт по имени/IP, отсутствие обхода VPN по IPv6.
6. Приложения: include/exclude, пустые списки, отсутствующий пакет. Сайты: direct/VPN и поддомены.
7. Wi-Fi -> мобильная сеть -> Wi-Fi, потеря сети, сон, отзыв разрешения и многократное подключение.
8. Регрессия sing-box: VPN, импорт, карта/ручной пинг (остаются на прежнем пути), часы,
   обучение, уведомление, обновления. Проверить независимость экспериментального пакета.
9. Сравнить CPU/RAM/батарею на одной сети и профиле, с одинаковой нагрузкой; зафиксировать методику.
10. Опубликовать только помеченный prerelease с исходниками и лицензиями. Не менять latest stable.

## Безопасный выпуск и откат

`realitypreview` имеет отдельный applicationId `.realitypreview` и имя NOVA VPN · Reality Test.
Он не заменяет установленную стабильную NOVA и не имеет доступа к её профилям/настройкам.
Версия 0.2.44 и latest стабильного релиза остаются неизменными. При любой проблеме можно
отключить тестовый VPN и пользоваться прежним приложением. Для `REALITY_PREVIEW` автоматическая
проверка стабильных обновлений отключена: ручная кнопка объясняет отдельный канал prerelease.
В обычных сборках `REALITY_PREVIEW=false`, существующая проверка обновлений не изменена.

## Воспроизведение Android smoke

Собрать `realitypreview` и instrumentation APK с `-PnovaRealitySmoke -PnovaRealityAbi=x86_64`.
Установить оба APK в одноразовый Android 15 эмулятор. Только для тестового пакета:

```text
adb shell appops set com.nova.vpn.android.realitypreview ACTIVATE_VPN allow
adb shell pm grant com.nova.vpn.android.realitypreview android.permission.POST_NOTIFICATIONS
adb shell am instrument -w com.nova.vpn.android.realitypreview.test/com.nova.vpn.android.RealityCoreSmokeRunner
```

Тест генерирует временный локальный TLS-сертификат и ключ в памяти; реальные профили не нужны.
Второе приложение с отдельным UID проверяет TUN/VLESS/TLS, IPv4/IPv6 и списки приложений.
Тестовые Activity и разрешения находятся только в instrumentation APK, не в приложении.

- GitHub Actions `38835664116`: сборка ARM64, ARMv7 и x86_64; нативные core-тесты —
  187 успешных, один пропущенный upstream-тест, без ошибок; FFI-тесты успешны.
- Android 15 / x86_64, отдельный тестовый пакет: проверка JNI/FD, восемь циклов
  SOCKS/start/stop, настоящий VpnService и локальный VLESS/TLS-сервер с временным CA.
- Отдельный UID приложения: TCP echo через TUN по IPv4 и IPv6, include/exclude списки,
  управляемое правило сайта при direct по умолчанию. Последнее проверяет реальный DNS
  fake-IP и передачу восстановленного домена в VLESS, а не только наличие JSON-правила.
- Отказ от смены живой конфигурации не останавливает текущий туннель; одно уведомление
  без звука/вибрации; последующее подключение sing-box проходит тот же TLS/TUN echo.
- Это локальный синтетический тест, не подтверждение работы всех провайдеров,
  REALITY/Vision/WS/gRPC, переходов сетей или экономии батареи на телефоне.
